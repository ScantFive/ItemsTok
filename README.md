# ItemsTok

Лента объявлений об аренде квартир с [Циан](https://www.cian.ru) в стиле Instagram.
TypeScript + Vite, без фреймворков.

Сайт: **https://scantfive.github.io/ItemsTok/**

- лента карточек с каруселью фото, бесконечная прокрутка;
- ♥ или двойной тап по фото — добавить в избранное;
- выбор города (запоминается);
- избранное хранится локально в браузере (`localStorage`), вместе с данными объявления.

## Что делать: пошагово

### Шаг 1. Один раз: включить GitHub Pages

1. Репозиторий на GitHub → **Settings → Pages**.
2. **Source: Deploy from a branch**, ветка **`gh-pages`**, папка **`/ (root)`** → **Save**.

Ветку `gh-pages` создаёт и обновляет workflow «Deploy to GitHub Pages» при каждом пуше.
Не выбирайте ветку с исходниками (`main` и т. п.) — там несобранный TypeScript, и страница будет белой.

### Шаг 2. Один раз: подготовить компьютер

Объявления скачиваются **с вашего компьютера**: серверам GitHub и Cloudflare Циан отвечает капчей,
а обычный домашний интернет пускает.

1. Установите [Node.js](https://nodejs.org) версии 20 или новее и [Git](https://git-scm.com/downloads).
   Проверка в терминале (на Windows — PowerShell):
   ```bash
   node -v   # v20.x или выше
   git --version
   ```
2. Скачайте проект и установите зависимости:
   ```bash
   git clone https://github.com/ScantFive/ItemsTok.git
   cd ItemsTok
   git checkout claude/adoring-edison-1b6dw8   # или main, когда ветку вольют
   npm install
   ```
3. Убедитесь, что `git push` работает (при первом пуше Git попросит войти в GitHub —
   через браузер или [personal access token](https://github.com/settings/tokens)).

### Шаг 3. Выгрузить объявления на сайт

```bash
npm run update-data
```

Команда:

1. скачивает по 3 страницы аренды для каждого из 10 городов в `public/data/<id региона>.json`;
2. делает коммит с этими файлами;
3. делает `git push` — это запускает пересборку сайта.

Через 1–2 минуты обновите сайт: над лентой будет написано
**«Объявления Циан, выгрузка от …»**. Ход сборки видно во вкладке **Actions → Deploy to GitHub Pages**.

### Шаг 4. Обновлять объявления

Когда захотите свежие объявления — в папке проекта:

```bash
git pull
npm run update-data
```

Удобно делать раз в день или пару раз в неделю. Часто запускать не нужно: Циан может начать просить капчу.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Белая страница | Проверьте шаг 1: в Pages должна быть выбрана ветка `gh-pages`. |
| «Приложение не запустилось…» | То же, что выше. |
| «…показаны демо-объявления» | Для этого города ещё нет выгрузки — выполните шаг 3. |
| `Циан попросил капчу — останавливаемся` | Циан временно ограничил запросы. Подождите час-другой и повторите. Уже скачанные города сохранятся. |
| `Не удалось скачать объявления` | Проверьте, что cian.ru открывается в браузере на этом компьютере, и пришлите вывод команды. |
| `Новых данных нет — отправлять нечего` | Всё в порядке, данные не изменились. |
| Ошибка при `git push` (`Authentication failed`, `403`) | Войдите в GitHub в Git (см. шаг 2.3) и повторите `git push`. |
| Объявления на сайте не обновились | Подождите 2 минуты и обновите страницу; проверьте, что последний запуск в Actions зелёный. |

Только скачать и закоммитить, без отправки: `npm run update-data -- --no-push` (потом `git push` вручную).

## Для разработки

```bash
npm run dev          # http://localhost:5173
npm test             # юнит-тесты
npm run fetch:cian   # скачать объявления в public/data без коммита
npm run build        # сборка в dist/
```

Порядок источников в приложении: выгрузка из `public/data` → живой запрос (только если при сборке
задан `VITE_CIAN_API`, см. ниже) → демо-данные для городов без выгрузки.

## Прокси для Циан (Cloudflare Worker, необязательно)

> Сейчас Циан часто отвечает этому прокси капчей, поэтому основной способ — `npm run update-data`.
> Без переменной `CIAN_API_URL` сайт к прокси не обращается.

`worker/index.ts` — узкий прокси: `GET /search?region=1&page=1` → `{ offers: [...] }`
(и `GET /debug` — что Циан отвечает прокси). Он ходит только в поиск аренды Циан, кэширует ответ
на 10 минут и отвечает браузеру только с сайтов из `ALLOWED_ORIGINS` (`worker/wrangler.toml`).

Развёртывание — workflow «Deploy CIAN proxy (Cloudflare Worker)»; нужны секреты репозитория
`CLOUDFLARE_API_TOKEN` (шаблон токена «Edit Cloudflare Workers») и `CLOUDFLARE_ACCOUNT_ID`
(строка после `dash.cloudflare.com/` в адресе кабинета). Чтобы сайт им пользовался, добавьте
переменную репозитория `CIAN_API_URL` = адрес воркера и перезапустите «Deploy to GitHub Pages».
